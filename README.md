# Software Development Life Cycle Portfolio submission

Interpreting User Needs and User Stories:
To interpret user needs, the Product Owner acts as a bridge between clients and the development team to keep the product backlog updated and prioritized. Creating user stories helps the Scrum team because they focus on the who, what, and why of a feature instead of getting lost in complex technical details. The simple language and value statements in these stories also help team members develop clear test cases to ensure the final program matches what the user expects.

Development Approaches and Agile Processes:
The Waterfall model is rigid and moves linearly through sequential phases, making it very difficult to adapt when user needs change. In contrast, the Agile framework uses short, week long sprints that let teams safely change direction, such as the sudden shift to detox and wellness destinations in the travel project. In future development work, I hope to incorporate core Agile processes like Sprint Planning, Daily Standups, Backlog Refinement, and Sprint Retrospectives, while using organizational tools like Jira to track team progress openly.

Effective Teamwork in Software Development:
Being a good team member in software development means working well in an autonomous, self organizing team where everyone believes that we are all in this together. It requires open communication during standard Scrum events and spreading discussions across the week so everyone has time to think before making final decisions. Good team members must also be flexible enough to help outside their strict roles, such as developers running test cases, while using clear communication to remain accountable.
